# The workout route is shown on Apple's map

**Date:** 2026-11-03
**Who decided:** mine
**Plan:** docs/plans/2026-11-03-workouts.md
**Amends:** `2026-10-26-no-cloud.md`, for map tiles only

## Context

The workout plan first drew the route as a plain line with no map, because a map behind it has to come from a map service. The owner wants to see where the route went.

## Decision

The Workout page shows the phone's route on Apple's map (MapKit, free). When the owner opens a workout page with a route, Apple's map tiles for the route's area are fetched from Apple. The route line, heart rate, times and the fact that it is a workout never leave the phone: Vesel draws the line on top of the tiles itself. No place search, no reverse geocoding, no Look Around, no directions. Without a connection the map shows its empty grid with the route still drawn on it; there is no second drawing of the route.

## Why

A route without streets around it doesn't say where you went. Apple's map is free, built in, and asks only for the area being looked at.

## Alternatives

A plain line with no map (nothing fetched; rejected: unreadable as a place). Another map service such as OpenStreetMap tiles (also a third party, and needs attribution and a tile server choice; no gain over Apple's).

## What it means

A named risk area in the plan: the only network call besides the owner's Mac is MapKit asking Apple for tiles of an area, and only while a workout page with a route is on screen. Health data and the route itself still go only to the owner's Mac. Any other use of a map service (search, place names, sharing) needs a new decision.
