# Hourly steps
**Date:** 2026-10-28
**Status**: Implemented 2026-10-28
**Touches**: `docs/design/screens.md` (Today, Journal, Steps page), `docs/how-it-works/days.md`, `CHANGELOG.md`

Decision: `docs/decisions/2026-10-28-hourly-steps.md`.

## TL;DR
- Journal: the Steps row becomes a card like Heart rate: total ("so far" today) and small bars per hour with 00:00 / 24:00; opens the Steps page.
- New Steps page (`PageRoute.steps(DayKey)`): total, "Through the day" bars, the 4-week card.
- Today's Steps card opens the page; Body's stays on the chart.
- VeselCore `HourlySteps` (minutes to wall-clock hours); VeselStorage `observeHourlySteps(day:)` reads `raw_export` `activitySamples`.
- No migration, nothing stored, nothing leaves the phone.

## Decisions
1. **mine** — Hourly steps come back (reverses the 2026-10-27 call).
2. **mine** — Journal card with bars; a Steps page modelled on Stress and Heart rate; Today opens it.
3. **agent's** — Hours are wall-clock hours read from each sample's own time text, so DST days still have 24 bars (the repeated hour is one bar, the skipped one has none). The chart's x axis is the hour number 0 to 24, not dates.
4. **agent's** — The page's total is the daily summary's (as Today shows); the hours are not reconciled with it.
5. **agent's** — The hours are read in the shown day's observation only (the samples JSON of that day, decoded on the reader's queue); Journal and the page each read it once per day.

## Deviations
- None from the brief. The hourly read re-runs when `raw_export` changes (the same region the fitness inputs read), not only when the shown day's row does.
